# GCP Project and IAM Setup Guide

## Overview
This document covers setting up a Google Cloud Platform (GCP) project with appropriate Identity and Access Management (IAM) configurations to support our DevOps infrastructure.

## Why This Matters
A properly configured GCP project with least-privilege IAM is the foundation for a secure cloud infrastructure. This provides:
- **Isolation**: Separate environments and resources
- **Access Control**: Limit who can do what
- **Security**: Reduce attack surface through limited permissions
- **Accountability**: Track who made what changes

## Prerequisites
- Google Cloud SDK installed and configured on your workstation
- Terraform installed (v1.0+)
- A Google account with permission to create projects
- Basic familiarity with command line operations

## Implementation Approach
We'll use both Google Cloud SDK commands and Terraform to define our GCP project and IAM settings as Infrastructure as Code (IaC), ensuring that our setup is reproducible and documented.

## Step-by-Step Implementation

### 1. Initialize Your Local Environment

```bash
# Make sure you have Google Cloud SDK installed
gcloud --version

# Install if needed (for Ubuntu/Debian)
# sudo apt-get update && sudo apt-get install google-cloud-sdk

# Log in to Google Cloud
gcloud auth login

# If working with an organization, set organization
# gcloud config set organization ORGANIZATION_ID
```

### 2. Create a GCP Project

```bash
# Create a new project
gcloud projects create devops-sprint1-project --name="DevOps Sprint 1"

# Set the project as your current project
gcloud config set project devops-sprint1-project

# Verify the project is set correctly
gcloud config get-value project
```

### 3. Enable Required APIs

```bash
# Enable the APIs we'll need for our infrastructure
gcloud services enable compute.googleapis.com
gcloud services enable container.googleapis.com
gcloud services enable containerregistry.googleapis.com
gcloud services enable iam.googleapis.com
gcloud services enable cloudresourcemanager.googleapis.com
gcloud services enable dns.googleapis.com
gcloud services enable storage-api.googleapis.com
gcloud services enable servicenetworking.googleapis.com

# Verify enabled APIs
gcloud services list --enabled
```

### 4. Set Up Billing (Important!)

```bash
# List available billing accounts
gcloud billing accounts list

# Link your project to a billing account
gcloud billing projects link devops-sprint1-project --billing-account=BILLING_ACCOUNT_ID
```

### 5. Create a Service Account for Terraform

```bash
# Create service account for Terraform
gcloud iam service-accounts create terraform-sa --display-name="Terraform Service Account"

# Grant necessary roles to the service account
gcloud projects add-iam-policy-binding devops-sprint1-project \
  --member="serviceAccount:terraform-sa@devops-sprint1-project.iam.gserviceaccount.com" \
  --role="roles/compute.admin"

gcloud projects add-iam-policy-binding devops-sprint1-project \
  --member="serviceAccount:terraform-sa@devops-sprint1-project.iam.gserviceaccount.com" \
  --role="roles/container.admin"

gcloud projects add-iam-policy-binding devops-sprint1-project \
  --member="serviceAccount:terraform-sa@devops-sprint1-project.iam.gserviceaccount.com" \
  --role="roles/iam.serviceAccountUser"

gcloud projects add-iam-policy-binding devops-sprint1-project \
  --member="serviceAccount:terraform-sa@devops-sprint1-project.iam.gserviceaccount.com" \
  --role="roles/storage.admin"

gcloud projects add-iam-policy-binding devops-sprint1-project \
  --member="serviceAccount:terraform-sa@devops-sprint1-project.iam.gserviceaccount.com" \
  --role="roles/dns.admin"

# Verify the roles assigned to the service account
gcloud projects get-iam-policy devops-sprint1-project \
  --filter="bindings.members:terraform-sa@devops-sprint1-project.iam.gserviceaccount.com" \
  --format="table(bindings.role)"
```

### 6. Create a Service Account Key

```bash
# Create a directory for credentials if it doesn't exist
mkdir -p ~/.gcp

# Create and download key for Terraform to use
gcloud iam service-accounts keys create ~/.gcp/terraform-sa-key.json \
  --iam-account=terraform-sa@devops-sprint1-project.iam.gserviceaccount.com

# Secure the key file with appropriate permissions
chmod 400 ~/.gcp/terraform-sa-key.json
```

### 7. Set Up Terraform Backend

```bash
# Create a GCS bucket for Terraform state
gsutil mb -p devops-sprint1-project gs://devops-sprint1-terraform-state/

# Enable versioning on the bucket for state history
gsutil versioning set on gs://devops-sprint1-terraform-state/

# Create a file structure for Terraform
mkdir -p ~/devops-project/terraform
cd ~/devops-project/terraform
```

### 8. Create Terraform Configuration Files

Create `main.tf`:

```terraform
# Set up the Google Cloud provider
provider "google" {
  credentials = file("~/.gcp/terraform-sa-key.json")
  project     = "devops-sprint1-project"
  region      = "us-central1"
}

# Set up remote state
terraform {
  backend "gcs" {
    bucket  = "devops-sprint1-terraform-state"
    prefix  = "terraform/state"
  }
}

# Create basic variables
variable "project_id" {
  description = "The GCP project ID"
  default     = "devops-sprint1-project"
}

variable "region" {
  description = "The GCP region to deploy resources"
  default     = "us-central1"
}

variable "zone" {
  description = "The GCP zone for zonal resources"
  default     = "us-central1-a"
}

# Output important information
output "project_id" {
  value = var.project_id
}

output "region" {
  value = var.region
}
```

### 9. Initialize and Test Terraform Configuration

```bash
# Initialize Terraform
terraform init

# Validate the configuration
terraform validate

# Create a plan to verify everything is set up correctly
terraform plan
```

## Troubleshooting

### Permission denied errors
- **Issue**: Getting "Permission denied" when running Terraform or gcloud commands
- **Solution**: Verify service account has proper IAM roles
  ```bash
  gcloud projects get-iam-policy devops-sprint1-project
  ```

### API not enabled
- **Issue**: "API not enabled" errors in Terraform or gcloud
- **Solution**: Check if required APIs are enabled
  ```bash
  gcloud services list
  ```

### Billing not set up
- **Issue**: "Billing is not enabled for this project" error
- **Solution**: Link your project to a billing account
  ```bash
  gcloud billing projects link devops-sprint1-project --billing-account=BILLING_ACCOUNT_ID
  ```

### Terraform state issues
- **Issue**: Terraform can't access state in GCS
- **Solution**: Verify permissions on the GCS bucket and make sure you're authenticated correctly
  ```bash
  gsutil ls -la gs://devops-sprint1-terraform-state/
  ```

## Integration with Other Components
- The project and IAM setup provides the foundation for all other resources
- The service account will be used by Terraform to provision VPC, GKE and Container Registry
- The IAM permissions will control what GitHub Actions can do during CI/CD

## Security Considerations
- The service account key should be stored securely
- Consider using more restricted roles when moving to production
- Follow the principle of least privilege for all accounts
